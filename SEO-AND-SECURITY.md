# SEO + security setup

## Before you deploy (2 minutes)
1. Set your real address at build time, e.g. `VITE_SITE_URL=https://www.your-domain.com`
   and `SITE_URL=` (same value). See `.env.example`. Without it the canonical link,
   og:url and og:image will be missing.
2. Build + deploy: `npm install && npm run build`.
3. Check `https://your-domain.com/robots.txt` and `/sitemap.xml` load.

## Get found on Google
1. Go to https://search.google.com/search-console and add your site (URL-prefix).
2. Choose the "HTML tag" method, copy only the `content` value, set it as
   `VITE_GOOGLE_SITE_VERIFICATION`, rebuild, deploy, click Verify.
3. Sitemaps > submit `sitemap.xml`. URL Inspection > paste your homepage > Request indexing.
4. Create/claim a free Google Business Profile for "Boonies Bakery Co, Kilgore TX".
   For a local bakery this matters more than anything on the site itself.
Indexing usually takes a few days to a few weeks; nobody can guarantee a ranking.

## What was added
- Title, meta description, canonical, Open Graph + Twitter cards, robots meta.
- JSON-LD `Bakery` + `WebSite` structured data (name, phone, email, city, Facebook).
- robots.txt and sitemap.xml (generated by the server; add new pages to `server/routes/sitemap.xml.ts`).
- Photos converted to WebP (about 0.8 MB total, down from 2.6 MB), responsive sizes, lazy-loaded below the fold, hero prioritised.
- robots.txt names Googlebot, Bingbot and OAI-SearchBot explicitly.
- Removed the Grok head injector, "Created with Grok" script and Grok install page, which
  overwrote Open Graph tags and loaded a third-party script from grok.com.

## Security
- `server/security-headers.ts`: CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy,
  Permissions-Policy, COOP/CORP. Applied to all responses via `routeRules` in `vite.config.ts`.
- `server/middleware/01-rate-limit.ts`: per-IP limits (120 req/min pages, 20 req/min API/POST),
  405 for odd HTTP methods, 414 for huge URLs, 429 + Retry-After when exceeded. Static assets exempt.
  Limits are per server instance (in memory). For a hard global cap also turn on your host's
  firewall rate limiting (Cloudflare / Vercel Firewall / Cloud Armor).
- The order form only builds a `mailto:` link in the browser; there is no database or form
  endpoint to attack. Login is disabled (`.grok/app-env.json`, keep that file).
- No site is "unhackable": keep dependencies updated (`npm audit`), use HTTPS only, and
  protect the hosting account and the Facebook/Gmail accounts with 2-factor authentication.
